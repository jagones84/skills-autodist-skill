# Safe Delete Advisor

## Overview

This skill turns the repository into an agent-ready workflow for **space recovery triage**.

It does **not** delete files on its own.
It audits disk usage, reads compact reports, and produces a shortlist of:

- delete first
- inspect before delete
- do not touch

The current `v1` runtime target is DGX/Linux with `ncdu`.

## When to Use

Use this skill when:

- the user asks what can be deleted to free disk space
- the machine has large caches, model files, partial downloads, or trash
- the user wants a safe shortlist, not blind cleanup
- the environment is DGX/Linux or similar and the repo tools are available

Do not use this skill when:

- the user wants automatic deletion without review
- the environment is unrelated to this repository and its scripts
- the task is generic system administration with no need for disk-space triage

## Safety Rules

- Never delete automatically.
- Suggest deletion only.
- Read compact outputs before raw exports.
- Treat partial downloads, trash, and cache as the first deletion class.
- Treat model assets, checkpoints, and live app inputs as `inspect before delete`.
- Treat Docker storage, swap, and system-owned paths as `do not touch`.
- If `ncdu` is missing and installation needs `sudo`, use the repo install path only; do not invent alternate flows.
- Never store credentials or passwords in the repository.

## Standard Workflow

### 1. Read State First

Read:

- `README.md`
- `.agent/HANDOFF.md`

If the repo already contains recent audit results or blockers, continue from there instead of redoing the whole flow.

### 2. Prepare DGX Scripts

Run:

```bash
ssh dgx bash /home/jagones/Repositories/disk-audit-dgx/scripts/dgx/prepare_linux_scripts.sh
```

Expected:

- `prepared_linux_scripts=yes`

### 3. Verify Scan Engine

Run:

```bash
ssh dgx /home/jagones/Repositories/disk-audit-dgx/scripts/dgx/verify_ncdu.sh
```

Expected:

- success path: `ncdu_path=...` and version
- missing path: error with non-zero exit code

If missing, use:

```bash
ssh dgx /home/jagones/Repositories/disk-audit-dgx/scripts/dgx/install_ncdu.sh
```

If this path still requires operator privileges, stop and ask for them. Do not invent package-manager shortcuts outside repo workflow.

### 4. Run The Read-Only Audit

Run:

```bash
ssh dgx /home/jagones/Repositories/disk-audit-dgx/scripts/dgx/run_audit.sh
```

Expected:

- a new run folder under `outputs/`
- a raw `ncdu-export.json`
- compact report files generated by the Python CLI

### 5. Read Compact Outputs

Run:

```bash
ssh dgx /home/jagones/Repositories/disk-audit-dgx/scripts/dgx/show_latest_audit.sh
```

Read in this order:

- `summary.md`
- `top_dirs.csv`
- `top_files.csv`
- `candidates.json`

Do **not** start from the raw export unless the compact reports are missing or clearly wrong.

### 6. Pull The Safe-ish Deletion Layer

Run:

```bash
ssh dgx /home/jagones/Repositories/disk-audit-dgx/scripts/dgx/find_safe_candidates.sh
```

This helper focuses on the highest-confidence deletion classes:

- large cache files
- partial downloads like `*.filepart`
- trash content

### 7. Classify Findings

Use these buckets:

- `delete first`
  - incomplete downloads
  - trash contents
  - large cache blobs that are redownloadable
- `inspect before delete`
  - `Programs/llama_cp/local/inputs/...`
  - `ComfyUI/models/...`
  - checkpoints, safetensors, gguf, live app inputs
- `do not touch`
  - `/var/lib/docker-loop.xfs`
  - `/swap.img`
  - `/etc`, `/usr`, `/boot`, `/var/lib`
  - anything clearly part of runtime/system storage

### 8. Produce The Final Suggestion

Return a deletion suggestion list grouped by:

- path
- size
- reason
- risk bucket

Preferred output order:

1. delete first
2. inspect before delete
3. do not touch

## Output Contract

The final answer should always contain:

- a short status line with whether the audit actually ran
- the latest run path
- the safest candidates first
- anything large that should *not* be deleted blindly
- the main reason for each recommendation

## Common Mistakes

- reading the raw `ncdu` export first and wasting tokens
- suggesting deletion of model assets only because they are large
- deleting Docker or swap storage
- skipping `find_safe_candidates.sh` and jumping directly to live assets
- reporting only file names without full paths
- treating “large” as equal to “safe to remove”
